## Internal Certificate Authorities

I (Rick) have added the in-house root certificate used by my employer (VSSI).

One function of the ZTRUST collection is to serve as a reference for
in-house CA root certificates. This particular root certificate is "detach
signed" using PGP, as is recommended for PKI certificates in the collection.
Further, it is signed using two different PGP keys. GPG correctly finds
both signatures and processes them individually, so this demonstrates
that we can have multiple PGP signatures on files. *Very* helpful.

## Keys for Service Accounts

Igor asked about keys which are not owned by any particular individual,
should they be included in the collection. I (Rick) responded that we (VSSI)
also have such a key and that they *should* be included. (They also *must*
be signed by actual humans in the supporting group or team.) For example,
the VSSI code-signing key bears an email address of "support@" and is
signed by two people (soon three) at VSSI. An email like that is a form of
service account, similar to identities which run tasks but which do not
relate to a particular person.
